# NOTE_ARTICLE.md — `/notes/[slug]`

## Goal

Create a first-class technical reading experience for architecture notes, experiments, postmortems and product/AI system thinking.

---

## 1. Article header

Include:

- back link to Notes
- category
- title
- description/deck
- date
- updated date when relevant
- reading time
- tags, restrained
- related project link when relevant

Hero image is optional, never mandatory.

---

## 2. Reading column

Target 60–75 characters per line.

Use generous top/bottom spacing around:

- H2/H3
- diagrams
- code blocks
- tables
- callouts

---

## 3. Technical content

Support:

- syntax-highlighted code
- architecture diagrams
- Mermaid only if styling can be controlled to match the system; custom SVG preferred for flagship articles
- tables
- warnings/notes
- performance charts
- embedded video

---

## 4. Callouts

Avoid generic colored alert boxes.

Use editorial callouts with:

- thin rule
- small mono label
- subtle warm background if needed

Types:

- Decision
- Tradeoff
- Failure mode
- Observation
- Result

---

## 5. Article navigation

- optional compact TOC for long pieces
- previous/next note only when useful
- related project at end

---

## 6. Visual treatment

Articles should be calmer than the homepage.

Use mostly paper/charcoal with terracotta headings/markers and cobalt only for technical/data emphasis.
